# Lumivox Codex Documentation Folder

This folder is the working instruction set for using Codex on the Lumivox website repository.

Lumivox is a practical smart-sleep and smart-living website focused on helping readers connect wearable sleep data, simple home automation, and beginner-friendly routines. The site is being developed as a content and affiliate-readiness project, with careful attention to tracking, content quality, product recommendations, media, and testing.

## How Codex Should Use This Folder

Codex should treat the files in this folder as the project memory and operating guide before making changes.

Before editing the site, Codex should read:

1. `PROJECT_STATE.md` — current understanding of the site.
2. `CODEX_INSTRUCTIONS.md` — rules and guardrails for Codex work.
3. `ROADMAP.md` — milestone direction.
4. `BACKLOG.md` — pending tasks and priorities.
5. `DECISIONS.md` — decisions already made so they are not reopened unnecessarily.
6. `TESTING_CHECKLIST.md` — what must be checked before saying work is done.

For content work, also read:

- `CONTENT_WORKFLOW.md`
- `ARTICLE_BRIEF_TEMPLATE.md`
- `SEO_CHECKLIST.md`
- `MEDIA_ASSET_GUIDELINES.md`
- `PAGE_EXPECTATIONS.md`

For tracking and affiliate readiness, also read:

- `AFFILIATE_TRACKING.md`
- `RELEASE_CHECKLIST.md`

## Documentation Maintenance Rule

Whenever Codex completes a meaningful task, it should update the relevant documentation file instead of relying on chat memory.

At minimum, Codex should update:

- `DEV_LOG.md` after each development or documentation pass.
- `BACKLOG.md` when new tasks are discovered or completed.
- `DECISIONS.md` when a project direction is chosen.
- `PROJECT_STATE.md` when the site structure, tracking approach, product stack, or content architecture changes.

## Repository Rule

This documentation folder is intended to guide the website project. It should not replace direct inspection of the current codebase. Codex must use the repository files as the source of truth whenever there is a conflict between documentation and actual code.
